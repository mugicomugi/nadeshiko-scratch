# ADR-008: なでしこ本体をフォークする条件

- **状態**: 提案中
- **日付**: 2026-09-16

## 状況

本プロジェクトは なでしこ3 の**公開APIとして保証されていない内部挙動7項目**（[nako-internals.md](../nako-internals.md) の I1〜I7）に依存している。

なでしこ3 は kujirahand 氏の単独開発である（open issues 223件、月1〜2回リリース）。3.7系で実際に破壊的変更があった（`__getProp`/`__setProp` の廃止、`@` の優先度変更、定数の書き換え禁止）。

**バス係数1のプロジェクトに依存している**という事実に、先に対処方針を決めておく。

## 決定

**原則としてフォークしない。上流 PR で解決する。**

ただし以下のいずれかに該当したら、**フォーク判断会議を開く**（フォークを決定するのではなく、判断する場を開く）:

- **(a)** 作者の活動が **6ヶ月停止**した
- **(b)** **I1〜I7 のうち2つ以上が同時に壊れた**
- **(c)** セキュリティ上の問題に **4週間対応がない**

## 根拠

フォークすると、バス係数1のプロジェクトを**こちらが引き取ることになる**。なでしこ3 は言語処理系であり、保守には言語実装の継続的なコミットが要る。本プロジェクトの主目的は教育サービスであって言語処理系の保守ではない。

一方で「絶対にフォークしない」と決めると、作者が離れたときに製品ごと止まる。**条件を先に書いておくことで、そのときに感情ではなく基準で判断できる。**

## 依存を減らすための構造的な手当て

1. **接触面を2パッケージに閉じ込める** — `@nb/nako-parser`（パース）と `@nb/nako-adapter`（実行）以外からの nadesiko3 の import を ESLint で禁止する
2. **nadesiko3@3.8.1 を pin する**
3. **週次 CI** で @latest に対する golden 実行と I1〜I7 の契約テストを回す。**失敗しても main は赤くせず Issue を自動起票**して追随コストを可視化する
4. 作品メタに `app.nadesiko3` のバージョンを焼き込み、実行時はその版のランタイムを読む（古い作品が動かなくなるのを防ぐ）

## 上流への貢献（関係構築として先に行う）

1. `nako_gen` への**軽量ガードオプション PR** — await / postMessage を伴わず、強制終了フラグを見て早期 return するだけの十数行の変更
2. **asyncFn 伝播と func_obj の挙動を doc 化する PR**

ドキュメント化されれば実質的に安定APIになり、破壊的変更時に気付いてもらえる。名称・ロゴの扱いの相談も同時に行う。

**接触のタイミングは未定**（Phase 0 のスパイク直後か Phase 1 完了後か）。スパイク S-04 / S-16 で「これは安定APIとして依存してよいか」を照会する必要があるため、Phase 0 中の接触が現実的。

## 再評価トリガー

- 上記 (a) / (b) / (c) のいずれか
- なでしこ3 に別のメンテナが加わり、バス係数が2以上になった → 依存面の許容範囲を広げてよいか再検討
