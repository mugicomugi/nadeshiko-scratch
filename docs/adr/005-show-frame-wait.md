# ADR-005: 毎フレーム待 は表示用コードにも出す（実行安全チェック は隠す）

- **状態**: 提案中
- **日付**: 2026-09-16

## 状況

生成されるなでしこコードには、子どもが書いていない行が2種類入る。

1. **`実行安全チェック`** — 暴走停止のためのガード命令（ADR-002）
2. **`毎フレーム待`** — `ずっと繰り返す` の本体末尾に自動挿入される協調並行のための待機

「ブロックで作ったものが、そのまま読める日本語のプログラムになっている」という中心命題がある以上、**どこまでを見せてどこからを隠すか**に一貫した線引きが要る。

## 決定

**`毎フレーム待` は表示用コードに出す。`実行安全チェック` は隠す。**

生成器は「表示用コード」と「実行用コード」の2系統を出力し、子どもに見せるのは表示用のみ。ただし `毎フレーム待` は表示用にも含める。

## 根拠

線引きの基準は「**その行がプログラムの意味の一部か、安全装置か**」。

- `毎フレーム待` は**プログラムの意味の一部**。「1回描いたら次のコマまで待つ」という、Scratch の `ずっと` が暗黙にやっていることの明示化であり、アニメーションの仕組みを理解するうえで教育的価値がある。隠すとテキストを持ち出して外部のなでしこ3で走らせたときに挙動が変わる
- `実行安全チェック` は**安全装置**であり、プログラムの意味には寄与しない。ループのたびに謎の行が挟まるのは読解の妨げにしかならない

## 影響

- **表示用テキストをそのまま外部のなでしこ3で走らせると、無限ループでブラウザが固まりうる。** 「コードは持ち出せる」という訴求には、ガードが有効であることを示すプラグマ1行を先頭に出して注意を促す
- `ずっと繰り返す` はなでしこ3の構文として存在しないため、プラグイン命令として定義し `には` 構文で本体を受ける（`ずっと繰り返すには … ここまで`）

## 再評価トリガー

- Phase 1 の V1（子どもへのヒアリング）で「`毎フレーム待` が何か分からなくて気になる」が過半 → 教材で説明を足すか、隠す側に倒す
